A language shaped around C

Familiar ground.
Less typing.

NanoC keeps C’s expressions, types, ABI, and toolchain. Its own syntax stays out of the way; when you need the underlying machine or compiler, it stays within reach. Generated code has no NanoC runtime.

Features

01 · LAYOUT

Blocks from whitespace

Bare return types, := inference, inline = expr bodies. No braces, colons or semicolons.

@f add(int a,b) int = a+b
@f main int
  result:=add(20,22)
  result!=42
02 · MACROS

Token templates

Captures, repetition, hygienic fresh identifiers and executable program macros.

@m twice($x)
  (($x)*2)
@f main int
  @twice(21)!=42
03 · COMPILE TIME

Generate code from code

@ct programs run during expansion and emit declarations, tables or whole modules.

@ct
  for i 1..4
    emit("@f item_"+str(i)+" int = "+str(i)+"\n")
04 · BUILD TIME

Scripted builds

@bt reads and writes files, inspects the environment and runs host commands. --check validates without touching the host.

@bt
  write("build/generated.h", "#define READY 1\n")
  run(["cc", "-c", "main.c"])
05 · ASSEMBLY

Drop to the instruction

Indented @asm with explicit outputs, inputs, clobbers and C jump labels. Instructions go to your target's assembler unchanged, on any architecture your compiler supports.

@asm volatile
  addl $1,%0
  out "+r"(count)
  clobber "cc"
06 · INTEROP

C and C++ as they are

Call any C header or C++17 API. --lang c++ enables C++ features; ABI and ownership stay yours.

#include <vector>
@f main int
  values:=std::vector<int>(3,2)
  sum:=0
  for value values
    sum+=value
  sum!=6
07 · BOOTSTRAP

The compiler speaks NanoC

63 modules

A C seed builds the self-hosted compiler; two generations must emit byte-identical C.

08 · TOOLING

Built for humans and agents

--describe prints the language, builtins and assembly cards. --check --diagnostics json gives machine-readable errors.

nanoc --describe syntax
nanoc --describe builtins
nanoc app.nc --check --diagnostics json
Runs where C runs

Any POSIX host.
Any C target.

The compiler is written in NanoC and bootstrapped from a C11 seed, so you only need a C11 compiler to start. Its output is portable C11 or C++17: whatever your compiler can build, NanoC can target. Only inline assembly is target-specific, and it is passed to your own toolchain.

Bootstrap notes ↗
  • Hosts Linux, macOS, BSD, WSL, MSYS2 (POSIX shell)
  • Compilers GCC, Clang, or any C11 cc
  • Output C11, or C++17 with --lang c++
  • Assembly your target's syntax, via GCC/Clang inline asm
  • Tested GCC + Clang, ASan/UBSan, a real musl C corpus

Install in one line

  
Get NanoC

  
Needs a POSIX shell and a C11 compiler (cc, gcc or clang). Installs into ~/.local by default.

  

    
Install
curl -fsSL https://raw.githubusercontent.com/mkalmousli/NanoC/main/install.sh | sh

    
Uninstall
curl -fsSL https://raw.githubusercontent.com/mkalmousli/NanoC/main/install.sh | sh -s -- uninstall

    
Update / editors
nanoc update                 # pull and rebuild the latest compiler
nanoc editor list            # detected editors are installed by default
nanoc editor install vim     # or vscode, neovim, emacs, micro, nano, sublime

  

  
Prefer a checkout? git clone https://github.com/mkalmousli/NanoC && cd NanoC && sh install.sh install. Custom location: add --prefix DIR.
