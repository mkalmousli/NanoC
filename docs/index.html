Language guide

Learn it in ten minutes.

Every example compiles and runs with the current compiler. Unmarked C stays valid, so you can adopt NanoC one function at a time.

01 · START

Hello, NanoC

Save this as hello.nc. Lines starting with # pass through unchanged, so any C header works.

#include <stdio.h>
@f main int
  puts("Hello from NanoC!")
  0

Build: nanoc hello.nc -o hello.c && cc hello.c -o hello && ./hello

02 · FUNCTIONS

Bare return types

The return type goes after the parameters, with no arrow. Omit it for void. Group parameters that share a type with a comma. A one-line body can be an = expression.

#include <stdio.h>
@f add(int a,b) int = a+b
@f greet(char *name)
  printf("hi %s\n",name)
@f main int
  greet("NanoC")
  printf("%d\n",add(2,3))
  0
  • An indented body returns its final expression. No return needed.
  • No braces, no semicolons, no parentheses around conditions.
03 · VALUES

Blocks produce values

An if/elif/else that covers every branch returns the value of whichever branch runs.

@f sign(int x) int
  if x<0
    -1
  elif x>0
    1
  else
    0
@f main int = sign(-9)!=-1
04 · LOCALS & LOOPS

Inference and ranges

:= infers the type of a scalar literal. for i 1..6 counts from 1 up to but not including 6.

#include <stdio.h>
@f main int
  total:=0
  for i 1..6
    total+=i
  printf("%d\n",total)
  0
  • Spell the type when you need it: int x=call().
  • Typed range: for i:size_t 0..n. Bounds are evaluated once.
  • Plain C loops still work: for int i=0;i<n;i++.
  • C++ iterates containers: for value values.
05 · MACROS

Token templates

@m defines a template. $x captures a token. A macro with = and no parameters is a named constant.

#include <stdio.h>
@m twice($x)
  (($x)*2)
@m answer = 42
@m maxfn($name,$type)
  @f $name($type a,b) $type = a>b?a:b
@maxfn(max_int,int)
@f main int
  printf("%d %d\n",@twice(@answer),max_int(2,3))
  0

Use $fresh(tmp) for generated names that must not collide. $$ writes a literal $.

06 · COMPILE TIME

Generate code with @ct

An indented @ct block runs during expansion. emit writes NanoC back into the source, so you can generate functions in a loop.

#include <stdio.h>
@ct
  f square(n) = n*n
  for i 1..5
    emit("@f square_"+str(i)+" int = "+str(square(i))+"\n")
@f main int
  printf("%d\n",square_4())
  0
07 · BUILD TIME

Files and commands with @bt

@bt is the only phase that may write files or run host commands. It runs before expansion. Use --check to validate a file without side effects; it rejects these calls.

@bt
  mkdir("build")
  write("build/nanoc-generated.h","#define GENERATED 42\n")
  emit(read("build/nanoc-generated.h"))
@f main int = GENERATED!=42
08 · ASSEMBLY

Inline assembly

An indented @asm block forwards instructions to the GCC or Clang inline assembler, with explicit out, in, clobber and labels sections. Assembly is the one target-specific part of NanoC.

Full syntax and examples: nanoc --describe asm or the assembly card ↗.

09 · INTEROP

C++17 and C headers

Headers work unchanged. Use --lang c++ to emit C++17 and get range loops over standard containers.

#include <vector>
#include <iostream>
@f main int
  values:=std::vector<int>(3,2)
  sum:=0
  for value values
    sum+=value
  std::cout<<sum<<'\n'
  0

Build: nanoc app.nc --lang c++ -o app.cc && c++ -std=c++17 app.cc -o app

Install in one line

Works on any POSIX host.

Install

git clone --depth 1 https://github.com/mkalmousli/NanoC && cd NanoC && cc -std=c11 -O2 build.c -o builder && ./builder install

Update

nanoc update

Fetches the latest source, rebuilds and reinstalls.

Uninstall

nanoc uninstall

Asks first. nanoc uninstall --yes skips the prompt.

Editors

nanoc editor list
nanoc editor install vim

Needs git and a C11 compiler (cc, gcc or clang). Installs to ~/.local by default; --prefix DIR changes it, --no-editors skips editor setup. Installs only the files it creates.
