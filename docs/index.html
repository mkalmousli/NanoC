A language shaped around C

Familiar ground.
Less typing.

NanoC keeps C’s expressions, types, ABI, and toolchain. Its own syntax stays out of the way; when you need the underlying machine or compiler, it stays within reach.

Read the compact language card ↗
01 LAYOUT

Blocks from whitespace.
Types without arrows.

@f add(int a,b) int = a+b

@f main int
  result:=add(20,22)
  result!=42

Indented bodies and bare return types keep routine C functions compact. Generated output is ordinary C11 or C++17.

02 MACROS

Shape syntax to fit.

@m twice($x)
  (($x)*2)

@f main int
  @twice(21)!=42

Token templates, captures, repetition, fresh identifiers, and executable program macros.

03 COMPILE TIME

Generate from small programs.

@ct
  for i 1..4
    emit("@f item_"+str(i)+" int = "+str(i)+"\n")

CT transforms code during expansion. BT can use host files and processes for builds.

04 ASSEMBLY

Drop to the instruction.

@asm volatile
  addl $1,%0
  out "+r"(count)
  clobber "cc"

Indented instructions with explicit outputs, inputs, clobbers, and C jump labels.

05 BOOTSTRAP

The compiler speaks NanoC.

63 modules

A C seed starts the build. Two self-hosted stages follow; every emitted module must match byte for byte.

How bootstrapping works ↗
06 BUILD TIME

Automate the build itself.

@bt
  write("build/generated.h", "#define READY 1\n")
  run(["cc", "-c", "main.c"])

Build time programs can read and write files, inspect the environment, and run host commands. Use --check to validate safely without host mutations.
